# GA4 구성·구현 순서

2026-10-17. 앱 코드 구현 단계. 모든 계정/설정/운영 실행은 미확인. 사용자 설정값·비밀 파일을 조회하지 않았다.

## 1. 사용자가 준비

| 할 일 | 명령·화면 절차 | 확인 |
| --- | --- | --- |
| GA4 속성 준비 | Google Analytics 관리에서 계정/속성 생성 또는 기존 사용, 보고 시간대 대한민국 선택 | 서비스용 속성과 한국시간 기준 확인 |
| 웹 스트림 | 데이터 스트림에서 웹 선택, 실제 운영 사이트 URL 입력 | 측정 ID 확인. Property ID와 혼동하지 않기 |
| 초기 측정 범위 | 확장 측정 비활성, 광고/Signals 연동하지 않음 | 수동 이벤트와 중복 없음 |
| 전달 | 공개 측정 ID와 실제 운영 도메인을 알려주기 | Google 비밀번호·API secret·서비스 계정 키 전달 불필요 |

메뉴 표기는 Google 화면 업데이트에 따라 다를 수 있다. 이번에 Google 계정이나 Cloudflare를 대신 설정하지 않는다.

## 2. 에이전트 구현

apps/web의 분석 어댑터·동의 UI·Today·좋아요, API/저장소·OpenAPI 계약·테스트를 작성했다. 검증 범위는 [진행 현황](05-진행현황.md) 참조. ID 미설정이면 분석은 비활성. 설정 파일은 직접 수정하지 않고 변경안을 문서로 제공한다. D1 테이블이 필요한 것은 Today/좋아요이며 GA4 태그 자체에는 D1이 필요 없다.

## 3. 설정과 데이터 준비 — 사용자

할 일: 측정 ID·운영 도메인·활성 플래그를 프로젝트 배포 구조에 맞게 설정하고 로컬 DB 변경안 적용.
명령: [설치 문서](ENGAGEMENT_INSTALL.md)의 실제 설정 계약과 SQL을 확인한다. 운영 적용 명령은 미확인.
확인: 공개 설정만 프런트에 포함, 운영 비밀 값은 번들에 없음, GA4 없는 상태에서도 뉴스 정상.

## 4. 검증

에이전트: 준비된 일회용 컨테이너에서 S1~S11 검증. 컨테이너가 없으면 시작/설치하지 않고 알린다. 최종 보완을 포함한 핵심 13개 테스트·타입 검사 통과. Linux 의존성 준비 후 전체 빌드·브라우저 E2E 확인 완료.
사용자: 최종 빌드·배포 후 분석 동의 → DebugView/Realtime 확인 → 기사 열기/좋아요 성공 이벤트 확인. 거절 상태에서는 Google 요청과 자체 방문 집계가 없어야 한다. Today는 집계 시작 이후 동의한 브라우저 기준임을 확인한다. GA4 보고서 지연을 실패로 오인하지 않는다.

## 5. 운영·되돌리기

GA 분석 플래그 비활성으로 전송 중지 가능하도록 구현. GA 장애가 뉴스 기능에 영향을 주지 않도록 한다. DB 테이블은 기능 비활성화만으로 삭제하지 않는다. D1 사용량·동의율·이벤트 중복을 관찰한다. 추후 동의 정책 변경이나 GA Data API 표시 통일은 별도 설계한다.

근거: [Google 웹 설정](https://developers.google.com/analytics/devguides/collection/ga4/web), [검증](https://developers.google.com/analytics/devguides/collection/ga4/troubleshoot), [데이터 지연](https://support.google.com/analytics/answer/11198161).


## 최신 검증 결과 (2026-10-17)

사용자 로컬 설치 예외 승인 후 Linux 의존성/Chromium 준비, 타입 검사·Vitest 합계63개·뉴스/관리앱 검증 빌드·브라우저14개 시나리오 확인 완료. 별도 핵심 Node 검사13개도 앞선 실행 통과. 브라우저 통계/좋아요는 모의 API이며 실제 로컬 D1은 별도 통합2개 검증. GA4 운영 수신·Cloudflare limiter·운영 DB 적용/배포는 미확인. 최신 결과는 [진행 현황](05-진행현황.md)을 따른다.
